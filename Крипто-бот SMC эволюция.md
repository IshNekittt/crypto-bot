## РАЗДЕЛ 1. РАСШИРЕННЫЕ ТИПЫ ДАННЫХ И ИНТЕРФЕЙСЫ

Для покрытия 11 сценариев, движок должен оперировать следующими сущностями:

- SwingPoint: { type: 'HIGH' | 'LOW', price: Decimal, timestamp: number, isSwept: boolean }

- LiquidityPool: { type: 'BSL' | 'SSL' | 'EQH' | 'EQL' | 'PDH' | 'PDL', priceLevel: Decimal, points: SwingPoint[], isTaken: boolean }

- Zone: { type: 'OB' | 'FVG' | 'BREAKER' | 'MITIGATION', top: Decimal, bottom: Decimal, timestamp: number, mitigated: boolean, timeframe: '15m' | '4h' }

- SessionRange: { name: 'ASIAN' | 'LONDON' | 'NY', high: Decimal, low: Decimal, start: number, end: number }

- TradingRange: { high: Decimal, low: Decimal, equilibrium: Decimal, isDeviated: boolean }

- Structure: { type: 'BOS' | 'CHOCH' | 'SMS' | 'IDM', price: Decimal, timestamp: number, isValidated: boolean }

## РАЗДЕЛ 2. ЖЕСТКАЯ МАТЕМАТИКА (PatternRecognizer) И ТРИ ЗОЛОТЫХ ПРАВИЛА

Движок должен уметь высчитывать концепты из OHLCV (через decimal.js). Внедряются три критических фильтра:

**ПРАВИЛО 1: Фактор времени (NY Time & Killzones)**
Сценарии работают ТОЛЬКО в активные торговые сессии. Бот должен использовать библиотеку таймзон (например, luxon или date-fns-tz), переводить UTC время биржи в America/New_York и учитывать переходы на летнее/зимнее время (DST).

- Asian Range: 20:00 - 00:00 NY

- London Killzone: 02:00 - 05:00 NY

- NY Killzone: 07:00 - 10:00 NY
  Снятие ликвидности вне этих зон игнорируется.

**Глобальная макро-структура (Исторический контекст):**
Для обхода проблемы ограниченности свечей, при старте бот скачивает по 1000 свечей для таймфреймов 1W (Неделя) и 1D (День). Из них извлекаются: ATH (All-Time High), ATL, исторические HTF FVG и Order Blocks. Эти координаты кэшируются как LiquidityPool и Zone, чтобы бот видел таргеты далеко "слева" на графике.

**ПРАВИЛО 2: Истинный импульс (Displacement)**

- BOS / CHoCH: Свеча пробития должна закрыться ТЕЛОМ за SwingPoint (close > price).

- Displacement: Тело пробивающей свечи должно быть > 1.5 \* ATR(10). Пробой должен быть полнотелым и быстрым. Если структура пробивается вяло (сползание из нескольких мелких свечей) — сетап отменяется.

**ПРАВИЛО 3: Золотое сечение 0.5 (Equilibrium)**

- В сценариях входа от FVG или Order Block, вход осуществляется строго от уровня 0.5 (середина зоны). Это снижает частоту сделок, но кардинально улучшает Риск/Прибыль (R:R).

- Общий Premium/Discount: Торговый диапазон = от SwingHigh до SwingLow. Лонги строго ниже 0.5 (Discount), шорты строго выше 0.5 (Premium).

**Дополнительные паттерны:**

- Sweep (SFP): Прокол тенью (high > price) и закрытие обратно (close < price).

- EQH / EQL: Два экстремума с разницей <= 0.05%.

- IDM (Inducement): Локальный экстремум перед глобальной POI (приманка).

- SMS (Smart Money Shift): Неспособность цены обновить предыдущий Хай/Лоу перед разворотом.

- **Глобальные уровни ликвидности (1D / 1W):** Помимо склейки PDH/PDL, бот должен раз в сутки через REST API запрашивать таймфреймы D (День) и W (Неделя) для точного определения PWH (Previous Weekly High), PWL (Previous Weekly Low), а также DO (Daily Open) и WO (Weekly Open). Эти уровни добавляются в массив LiquidityPool и выступают магнитами для Сценариев 5 и 7.

## РАЗДЕЛ 4. ДЕТАЛИЗАЦИЯ 11 SMC СЦЕНАРИЕВ (Для имплементации)

### Группа А: Продолжение тренда (Trend Continuation)

- **Сценарий 1: HTF Continuation.** 4H тренд. Цена касается 4H OB. Ждем на 15m CHoCH (с жестким Displacement). Вход от 15m FVG.

- **Сценарий 2: FVG Fill.** Сильный импульс, формирование крупного HTF FVG. Цена корректируется. Триггер: касание ровно уровня 0.5 (Equilibrium) HTF FVG. После этого ищем 15m CHoCH и входим.

- **Сценарий 3: Inducement (IDM).** Формируется локальный минимум (IDM), ниже которого находится настоящий OB. Цена резко прокалывает IDM тенью (Sweep) и тестирует OB. Вход по рынку сразу после закрытия свечи SFP.

- **Сценарий 4: Mitigation Chain.** Направленный тренд без откатов. Формируется новый OB. Триггер: возврат цены ровно к 50% тела этого OB (в касание, лимитом, без ожидания LTF слома).

### Группа Б: Развороты тренда (Reversals)

- **Сценарий 5: HTF Liquidity Sweep.** Цена подходит к PDH/PDL или BSL/SSL. Фильтр Killzone: должно быть активное время. Резкий прокол тенью (SFP) и закрытие обратно. Сразу после этого агрессивный CHoCH на 15m. Вход от 15m FVG.

- **Сценарий 6: Failure Swing (SMS).** Восходящий тренд не может обновить максимум (SMS). Затем агрессивный импульс вниз ломает структуру (CHoCH). Вход от Ордер Блока, сформировавшего этот SMS.

- **Сценарий 7: Модель AMD.** Фильтр Killzone: Работа на стыке сессий. Цена зажата в Asian Range (00:00-06:00). Импульс вниз пробивает Asian Low (сбор стопов) и возвращается (SFP / CHoCH вверх). Вход в лонг. Цель — Asian High.

### Группа В: Работа в Боковике (Ranges)

- **Сценарий 8: Range Deviation & Reclaim.** Выявлен TradingRange. Выход за Range High, но без закрепления. Агрессивный возврат внутрь. Фильтр Killzone: Только Лондон/Нью-Йорк. Вход на ретесте Range High изнутри. Цели: 0.5 и Range Low.

- **Сценарий 9: Turtle Soup (Range SFP).** Четкий боковик с EQH/EQL. Цена прокалывает границу тенью и моментально закрывается внутри. Вход по рынку в момент закрытия свечи. SL за кончик тени.

### Группа Г: Продвинутые зоны (Advanced POI)

- **Сценарий 10: Breaker Block Entry.** Сильный OB пробит импульсной свечой НАВЫЛЕТ (закрытие телом). OB превращается в Breaker Block. Ждем зеркального возврата цены. Наличие FVG обязательно. Вход от границы Брейкера.

- **Сценарий 11: Mitigation Block.** То же, что Брейкер, но перед пробоем цена сделала Failure Swing (SMS - не обновила экстремум). Вход на зеркальном ретесте.

## РАЗДЕЛ 5. НАБЛЮДАЕМОСТЬ И ДЕПЛОЙ (Supabase + Render.com)

**1. База Данных PostgreSQL (Supabase):**

- Используем библиотеку `pg`. Подключение строго через `process.env.DATABASE_URL` (строка из Supabase).
- Таблица `trades`: `id`, `symbol`, `scenario_id`, `entry`, `sl`, `tp`, `pnl`, `status`, `timestamp`, `reason`.

**2. Платформа Render.com (Stateless Web Service):**

- HTTP health-check сервер (`express` или `http`) слушает `process.env.PORT`. Маршрут `GET /` отдает `200 OK`.
- Никаких локальных Volumes (файлов), контейнер эфемерный.

**3. Telegram-Алерты (HTML) и БЭКАПЫ:**

- Для работы с Телеграм используй библиотеку telegraf (Long-Polling).

- **Режим AUTO_TRADING=true:** Бот сам входит в сделку и шлет отчет.

- **Режим AUTO_TRADING=false (Полуавтомат):** Бот НЕ отправляет ордер. Он сохраняет сетап в кэш PendingTrades, ставит таймер на TRADE_APPROVAL_TIMEOUT_MINUTES и шлет в ТГ сообщение с Inline-кнопками: [✅ Войти в сделку] и [❌ Отменить].

- Если пользователь жмет ✅ до истечения таймера, бот исполняет ордер.

- Если жмет ❌ или таймер истек — сделка аннулируется (тайм-аут рынка).

**4. Логи (winston):**

- Каждое действие математики пишется в консоль с указанием причин отмены сценариев. (например: "Сценарий 5 отменен: нерабочее время (вне Killzone)" или "Отмена: Displacement меньше 1.5 ATR").
